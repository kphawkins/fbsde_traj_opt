DT-FBSDE · equations as implemented

From value function to policy, and back to targets

The equations DT-FBSDE uses to turn a value function into a policy, and to turn that policy into regression targets for the next value function, written from the code in the exp/ilqr-mppi-comparison worktree. Each equation names where it lives. The last sections cover the grid reference and the oracle experiment whose result prompted this page, and where they differ from DT-FBSDE.

Notation: stage \(k = 0,\dots,K\); state \(x \in \mathbb{R}^n\); one control \(u \in [-1, 1]\); \(\tilde V_k\) is the fitted value function at stage \(k\). A set of value functions means all of \(\tilde V_0,\dots,\tilde V_K\) together (the code calls it a value-function table). For a degree-4 polynomial on the 2-D problems that's 65 polynomials of 15 coefficients each.

1. The problem every method solves

One step of the discrete-time model is control-affine with additive Gaussian noise:

\[ x_{k+1} = x_k + f_k(x_k) + B_k(x_k)\,u_k + \Sigma_k\,w_k, \qquad w_k \sim \mathcal N(0, I). \]

ComposedForwardSdeModel::operator(), sde/composed_forward_sde_model.hpp:60

  • Double integrator: \(f\) and \(B\) come from zero-order-hold discretization of a unit mass, with \(\Delta t = 1/16\) s.
  • Pendulum: \(f\) and \(B\) come from the held-control flow map \(\Phi(x, u)\), integrated by RK4 with 2 substeps: \(f(x) = \Phi(x, 0) - x\) and \(B(x) = \tfrac12[\Phi(x, 1) - \Phi(x, -1)]\). This is exact at \(u = 0\), and at \(u = \pm1\) up to the map's curvature in \(u\). examples/l1_benchmark_models.hpp:159–186
  • Noise: \(\Sigma = \operatorname{diag}(\sigma)\sqrt{\Delta t}\), with \(\sigma = (0.01, 0.1)\) for the double integrator and \((0.04, 0.4)\) for the pendulum. l1_benchmark_models.hpp:91, 200

The cost is fuel plus a quadratic terminal penalty:

\[ J = \mathbb E\Big[\sum_{k=0}^{K-1} c\,|u_k| \;+\; x_K^\top F\, x_K\Big], \qquad c = \Delta t, \]

\(F = \operatorname{diag}(20, 10)\) for the double integrator and \(\operatorname{diag}(10, 1)\) for the pendulum; \(K = 64\) for both. l1_benchmark_models.hpp:92–96, 201–205

All methods, the grid reference included, use this same discrete model, so their costs are directly comparable.

2. Policy from the value function

The Taylor Q-function

The policy at stage \(k\) reads only the next stage's fitted value function \(\tilde V_{k+1}\). With \(m(x, u) = x + f_k(x) + B_k(x)\,u\) the noise-free landing point and \(S_k = \Sigma_k\Sigma_k^\top\) the step's noise covariance,

\[ \tilde Q_k(x, u) \;=\; c\,|u| \;+\; \tilde V_{k+1}\big(m(x,u)\big) \;+\; \tfrac12 \operatorname{tr}\!\big(S_k\,\nabla^2 \tilde V_{k+1}(m(x,u))\big). \]

TaylorQFunctionL1Policy::QValue, policies/taylor_q_function_l1_policy.hpp:203–210 (thesis eq. 4.65)

This is the second-order expansion of \(\mathbb E_w[\tilde V_{k+1}(m + \Sigma w)]\). It is exact when \(\tilde V_{k+1}\) is quadratic. For a degree-4 polynomial it drops the fourth-order term \(\tfrac{1}{8}\,\mathbb E[(w^\top\Sigma^\top \nabla^4 \tilde V\,\Sigma w)]\)-type contributions, which scale with \(\|\Sigma\|^4\) and are tiny here (\(\Sigma\) is at most 0.1 per step).

The minimization

\[ \mu_k(x) \;=\; \operatorname*{arg\,min}_{u \in [-1,1]} \tilde Q_k(x, u). \]

TaylorQFunctionL1Policy::Decide, taylor_q_function_l1_policy.hpp:123–173 (thesis eq. 4.67)

Starting from \(u = 0\), the code makes 3 sweeps. Each sweep builds a local model of \(\tilde Q\) around the current control \(t_0\), using the gradient \(g\) and Hessian \(H\) of \(\tilde V_{k+1}\) at the current landing point and the control column \(b = B_k(x)\):

\[ \phi(t) = c|t| + \beta\,(t - t_0) + \tfrac{\alpha}{2}(t - t_0)^2, \qquad \beta = g^\top b,\quad \alpha = b^\top H b. \]

The candidates are \(\{-1,\ 0,\ 1\}\) and, when \(\alpha > 0\), the stationary point on each side of the kink, clamped to the box and kept only if it lies on that side:

\[ t_+ = t_0 - \frac{\beta + c}{\alpha}\ \ (\text{kept if } t_+ > 0), \qquad t_- = t_0 - \frac{\beta - c}{\alpha}\ \ (\text{kept if } t_- < 0). \]

Every candidate is scored by the exact \(\tilde Q_k\), not by \(\phi\), and the lowest wins. So the local model only proposes candidates and never decides.

3. Targets for the next value function

The backward pass runs from \(k = K-1\) down to 0. \(\tilde V_K\) is the terminal cost, exactly, and is never refit. At every sampled state \(x_s\) of stage \(k\), the target is a Q-value from the tables of stage \(k+1\). Which tables, and which control, depends on the backward target. The configuration used throughout (ff's) is double estimation.

Double estimation (the default here)

The batch is split into two halves, \(h \in \{0, 1\}\). Each half has its own table \(\tilde V^{(h)}\). For a sample in half \(h\), the control is chosen by that half's policy and the target is scored by the other half's Q-function:

\[ u_s = \mu^{(h)}_k(x_s), \qquad y_s = \max\!\Big(\tilde Q^{(1-h)}_k(x_s, u_s),\ y_{\min}\Big), \qquad y_{\min} = 0. \]

DtFbsdeIterativeSolver::DoubleGreedyBackwardPass, solvers/dt_fbsde_iterative_solver.hpp:1054–1130

Both \(\mu^{(h)}_k\) and \(\tilde Q^{(1-h)}_k\) read stage \(k+1\) of the half-tables, which were fitted earlier in the same backward pass. The two half-fits are averaged coefficient by coefficient into the pass's result: \(\theta_k = \tfrac12(\theta^{(0)}_k + \theta^{(1)}_k)\). :1127

Single table (option kCurrentPolicy)

\[ u_s = \mu^{\text{cur}}_k(x_s), \qquad y_s = \max\!\Big(\tilde Q^{\text{fit}}_k(x_s, u_s),\ 0\Big), \]

The control comes from the current, accepted table. The Q-value comes from the table fitted earlier in this pass. BackwardPass, :1005–1050

Slope targets (slope matching)

The target's gradient, holding the control fixed and dropping the noise term's third-derivative part, is the discrete costate recursion:

\[ G_s = J(x_s, u_s)^\top\, \nabla \tilde V^{(1-h)}_{k+1}\big(m(x_s, u_s)\big), \qquad J = \frac{\partial\,[x + f_k(x) + B_k(x)u]}{\partial x}\Big|_{x_s,\,u_s}. \]

TaylorGradientTarget, solvers/taylor_gradient_target.hpp:30–49. J is by central differences of the noise-free step, with relative half-width 10⁻⁵.

Only the slope along a control column is matched:

\[ t_s = b_s^\top G_s, \qquad b_s = B_{k-1}(x_s)\ \ (B_0(x_s) \text{ at } k = 0). \]

SetSlopeTargets, dt_fbsde_iterative_solver.hpp:1253–1265

The direction is the previous stage's control column, because stage \(k-1\)'s policy compares \(\tilde V_k\) along it. A target below the floor gets a zero gradient.

4. The fit, the blend and the line search

Each stage (each half, under double estimation) is fitted by weighted least squares with slope rows and a ridge. With \(\phi\) the basis and \(S\) the number of samples:

\[ \theta_k = \operatorname*{arg\,min}_\theta \sum_{s} \omega_s\Big[\big(\phi(x_s)^\top\theta - y_s\big)^2 + \gamma\,\big(b_s^\top \nabla\phi(x_s)^\top \theta - t_s\big)^2\Big] + \lambda S\,\|\theta\|^2 . \]

LinearBasisValueFunctionApprox::AccumulateNormalEquations / FitNormalEquations, value_function/linear_basis_value_function_approx.hpp:188–245, 395–420; the same for PolynomialValueFunctionApprox:202–280

Settings: \(\gamma = 1\) (pendulum) or 10 (double integrator), and \(\lambda = 10^{-6}\). The basis is the monomials of total degree ≤ 4 in \(z = (x - \text{center}) \oslash \text{scale}\), with gradients carried back by the chain rule.

The sample weights are local-entropy weights on the path-integrated heuristic \(\rho_s = a_s + y_s\), where \(a_s\) is the running cost the sample accrued to reach its state:

\[ \omega_s = \exp\!\Big(-\frac{\rho_s - \min_r \rho_r}{T\cdot \operatorname{sd}(\rho)}\Big), \qquad T = 2. \]

SampleWeights, dt_fbsde_iterative_solver.hpp:1150–1162 (thesis eq. 5.12, 5.15)

The fitted table is not adopted outright. It's blended with the current one, \(\theta \leftarrow (1-\eta)\,\theta^{\text{cur}} + \eta\,\theta^{\text{fit}}\), with \(\eta = 1, \tfrac12, \dots, \tfrac1{128}\). The first blend whose policy has a lower mean cost on 256 fixed evaluation rollouts is accepted. BlendIntoTrial :1137; line search :490–530

5. The grid reference (the "optimum")

On a 401 × 401 node grid with bilinear interpolation, backward from \(V_K(x) = x^\top F x\):

\[ V_k(x) = \min_{u \in \mathcal U_{41}} \Big[ c|u| + \sum_{j=1}^{9} \omega_j\, V_{k+1}\big(x + f_k(x) + B_k(x)u + \Sigma\,\xi_j\big) \Big], \]

\(\mathcal U_{41}\) is 41 evenly spaced controls in \([-1, 1]\). \((\xi_j, \omega_j)\) is the 3 × 3 tensor Gauss–Hermite rule, with nodes \(\{-\sqrt3, 0, \sqrt3\}\) and weights \(\{\tfrac16, \tfrac23, \tfrac16\}\) per axis. States off the grid read its nearest boundary value. The grid's policy is the same minimization evaluated at the actual state. examples/l1_grid_dp_reference.hpp:154–193

Its expectation is a quadrature, not the Taylor expansion of section 2. With bilinear interpolation, \(V_k\) is only piecewise linear between nodes, so its curvature exists only at cell boundaries and averages out through the quadrature.

6. The oracle experiment that raised the question

The oracle fit each stage's \(\tilde V_k\) directly to the grid's \(V_k\), then scored the policy of section 2 on that table:

\[ y_s = V_k(x_s), \qquad t_s = b_s^\top \widehat{\nabla V_k}(x_s), \qquad \widehat{\nabla V_k} \text{ by central differences of the grid}. \]

MakeOracleData / RunOracle, examples/value_model_study_main.cpp:386–522

  • States: 512 per stage, from rollouts of the grid's own policy, half at the problem's noise and half at 6×, clipped to the grid box.
  • Fit: the same weighted fit as section 4, with the same entropy weights, \(\gamma = 1\) and \(\lambda = 10^{-6}\).
  • Slope directions: stage \(k\)'s own column \(B_k(x_s)\). That's identical here to DT-FBSDE's \(B_{k-1}(x_s)\), because \(B\) doesn't depend on the stage in either benchmark.

Results on the pendulum:

  • Degree 4: a policy 81% above optimal, with value RMSE 0.73.
  • Degree 10: +10%, with RMSE 0.49.
  • Best of any model: about +9%.
  • DT-FBSDE with degree 4: +3.6%.

7. Differences and suspects found while writing this

None of these is confirmed as the cause; section 9 tests them. They're the places where what's fitted, or how it's used, differs between the oracle and DT-FBSDE, or between theory and code.

Degree 4 was not well fitted in the oracle. Its pendulum value RMSE (0.73) is the worst of the polynomial models, on values of order 1–3. So the +81% may simply be a capacity limit. The puzzle that remains is narrower: no model's oracle fit got below about +9%, while DT-FBSDE's own degree-4 fits reach +3.6%.

The oracle had no probes. DT-FBSDE adds one-step branches under \(u \in \{-1, 0, 1\}\) from its paths, which put samples exactly where the policy's minimization reads \(\tilde V_{k+1}\). The oracle sampled only the grid policy's rollouts (half at 6× noise). If the fit is poor at the landing points of controls the optimal policy doesn't choose, the oracle's policy can pick them.

The oracle fits values, DT-FBSDE fits Q-values of its own policy. DT-FBSDE's targets are \(\tilde Q\) evaluated with the next stage's fitted table. They are consistent with how the policy reads that table, including its Taylor approximation and its errors. The oracle's targets are the true \(V_k\), with no such consistency. The two only coincide if the model can represent \(V\) well.

The grid's own slopes are unreliable. The oracle's slope targets are finite differences of a bilinear interpolant, piecewise constant between nodes and steppy across them. Matching them may pull the fit's slopes away from the smooth truth, and slopes are what the policy reads.

Untested equation paths. Section 8 lists which of the equations above have a unit test that checks their value directly, and which are only exercised indirectly.

Two experiments would separate these:

  • Oracle with probes: add DT-FBSDE-style probe states to the oracle's training data.
  • Exact-expectation policy: score the oracle tables with an exact-expectation policy (Gauss–Hermite, as the grid does) instead of the Taylor Q-function. That isolates the Taylor step from the fit.

A side finding from the grid tests. Bilinear interpolation always overestimates a convex value function, and the grid applies it at every stage, so its error compounds. On the coasting double integrator the error is +0.59 at 140 cells, +0.17 at 280 and +0.043 at 560, on a value of 6.78. That's clean second-order convergence, so the Bellman step is correct. At the 400 cells used throughout, the grid's value function is about 1% high on that problem. The reported "optimum" is the held-out cost of the grid's policy, so it remains an honest upper bound on the true optimum. But gaps of a few tenths of a percent, like DT-FBSDE's +0.2–0.3% on the double integrator, are within the reference's own accuracy.

Conclusion of the audit: no implementation error was found in the policy, the targets, the slope targets, the fit, or the grid reference. That makes the oracle result more likely to come from the theory or the experiment's design than from a bug, which the next investigation addresses directly.

9. Follow-up experiments: is it the Q-function, the weights, or the fit?

Section 8 found no implementation error, so these experiments asked where the oracle's poor policies come from. All use the degree-4, 6 and 10 monomial polynomials and the same 1,024 held-out rollouts; gaps are against the grid's policy.

9.1 The Q-function policy is not the limit

9.2 Entropy weights: decisive for the oracle, minor for DT-FBSDE

Sweeping the temperature \(T\) of section 4's weights, from 0 (equal weights) to 16:

  • Oracle fits, pendulum: concentrated weights (\(T\) = 0.25–0.5) gave the best value error on the optimal trajectories (RMSE 0.19–0.24) and catastrophic policies (+1,100% to +2,300%). On the states those policies actually visited, the fits were off by 18–31. The fit is accurate where the weights concentrate and badly biased elsewhere; once noise pushes a rollout off the well-fitted region, its decisions run away. \(T\) = 2 was best for every degree.
  • Oracle fits, double integrator: the opposite. Lower temperature helps steadily (degree 4: +42% equal weights, +12.7% at \(T\) = 2, +5.2% at \(T\) = 0.25). Its linear dynamics don't run away.
  • DT-FBSDE (degree 4, 5 seeds): pendulum medians are +4.0%, +5.7%, +5.0%, +3.6%, +3.4% and +3.4% for \(T\) = 0, 0.5, 1, 2, 4 and 8. Only \(T\) = 0.5–1 is worse, with one seed at +16%. On the double integrator every setting lands within 0.1 points. The current \(T\) = 2 is fine.

9.3 Training on the policy's own states (DAgger) doesn't fix the oracle

The oracle was refit for six rounds, each adding 512 states per stage from rollouts of its own current policy, labeled with the grid's values and slopes. The policy did not improve:

  • Pendulum, degree 10: +10.4% before, +10.7% after six rounds.
  • Pendulum, degree 4: +81% before, +84% after (+43% to +128% in between).
  • Double integrator, degree 4: worse, from +12.7% to +24.5%.

Adding DT-FBSDE-style probes improved the first round by about a point, without a lasting effect. So the oracle wasn't failing because it trained on the wrong states.

  • Double integrator: DT-FBSDE's value functions are 4–7× less accurate than the oracle's, yet give a policy 25–40× closer to optimal. Much of their error is a constant offset (DT-FBSDE's estimate of the optimal cost was 148% high here), which no decision sees. Even the slope error, averaged over visited states, doesn't explain the difference. In a bang-off-bang problem what matters is the slope exactly where it crosses the fuel weight \(c\), at the switching boundary, and an average dilutes that.
  • Pendulum: the slope error along the control column does track policy quality, and DT-FBSDE's is the smallest, 2–10× below the oracle fits'.

Current explanation. The oracle's least-squares fit minimizes an error that isn't the one decisions depend on, and with a model too simple to represent the true value function, the best-fitting coefficients and the best-deciding coefficients differ. DT-FBSDE's line search accepts a set of value functions only when its rollouts get cheaper, so it effectively searches coefficients for decision quality. That would also explain the earlier findings: more data per fit, memory, replay and deterministic sigma points all made each fit more accurate, and all made DT-FBSDE worse. There's a known parallel in reinforcement learning: on Tetris, Szita and Lőrincz (2006) found that searching a linear value function's weights directly by rollout cost, with the noisy cross-entropy method, beat regression-based approximate dynamic programming by orders of magnitude.

What this suggests trying:

  • Fits that weight errors by their effect on decisions: slope accuracy near switching boundaries, \(|b^\top\nabla\tilde V| \approx c\).
  • Making DT-FBSDE's implicit policy search explicit: several proposals per iteration, kept or dropped by rollout cost.
